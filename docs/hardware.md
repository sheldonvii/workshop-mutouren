# 硬件接口与电气规格

本文档说明 K3 的引脚定义、转接板映射、云台与摄像头规格、供电要求，以及 Linux GPIO 字符设备与实时调度权限配置。

重要操作规范：插拔 FPC 排线前必须切断 K3 电源；正式运行建议使用 5V 3A 独立电源为舵机供电并与 K3 共地，排查与测试阶段可临时复用 K3 FPC 的 3.3V 引脚供电。

## 硬件清单

| 部件 | 型号与规格 | 说明 |
| --- | --- | --- |
| 主控 | SpacemiT K3 Pico-ITX（Bianbu 4.0.7，Linux 内核 6.18.3） | 26 针 FPC 接口引出 SoC GPIO 与外设总线 |
| 云台 | 松甲（Yeahbot）二维云台（96×90×146mm，自重 308g） | 铝合金支架，水平 270°、垂直 220°，有效负载约 500g |
| 舵机 | 2× PWM 舵机（TB S-K15 / S-K20，扭矩 15 / 20 kg·cm） | 铜合金齿轮，内置堵转保护，无位置反馈 |
| 摄像头 | W19 HD Webcam（USB UVC 协议） | MJPG 1280×720@30fps 定焦模组，固定于云台负载板 |
| 电源 | 推荐 5V 3A 直流稳压电源（或 5～8.4V 独立供电） | 推荐独立供电；现场调试缺乏外接电源时，可临时接 K3 FPC 的 3.3V 引脚供电 |

转接板用于将 K3 板载 26 针 FPC 转换为 2.54mm 标准排针。由于市售转接板引脚排布存在差异，使用前需实测核对线序定义。

## K3 引脚与转接板映射

K3 Pico-ITX 26 针 FPC 接口中涉及的引脚定义如下。`RX_PWM1` 与 `RX_PWM2` 在 SoC 侧对应 `d4019000.gpio-bank0` 控制器的第 28、29 根线。用户空间申请对应 GPIO 线时，内核 pinctrl 驱动会自动切换引脚复用模式至 GPIO，无需手动定制设备树。

| K3 FPC 物理引脚 | SoC 引脚名称 | GPIO 硬件线号 | 用途 |
| --- | --- | --- | --- |
| 2 | 3.3V | — | 3.3V 直流参考电平 |
| 11 | RX_PWM1 | bank0 偏移 28 | 备用（未接入） |
| 12 | RX_PWM2 | bank0 偏移 29 | 舵机脉冲输出信号线 |
| 26 | GND | — | 逻辑参考地 |

### 转接板引脚倒序规律

当前配套的转接板与排线连接后呈现镜像倒序特性：

$$
n_{\text{转接板}} = 27 - n_{\text{K3}}
$$

基于此规律，转接板排针实际接线对应如下：

| 转接板物理引脚 | 对应 K3 引脚 | 功能定义 | 实际线色标识 |
| --- | --- | --- | --- |
| 15 | 12 | 舵机 PWM 信号 (RX_PWM2) | 白线 |
| 1 | 26 | 系统地 (GND) | 黑线 |
| 25 | 2 | 3.3V 参考供电 | 红线 |

其他可用参考引脚：GND 位于 1、4、7、10、19、22 号，3.3V 位于 25、26 号。转接板 16 号引脚对应 K3 第 11 脚（RX_PWM1），本项目未使用，请勿误接。

### 引脚定义测量确认步骤

更换硬件批次或转接板时，按以下步骤实测核准引脚分配：

1. 切断 K3 电源，锁紧 FPC 排线（排线金手指朝向插座底面导通）。
2. 接通系统电源，使用万用表直流电压档测量各排针对 GND 电位，区分 3.3V 与逻辑地。
3. 停止运行游戏主服务，执行 `python tools/servo_gpio_test.py --blink` 使目标引脚交替输出高低电平。万用表测得周期性电平跳变的针脚即为 RX_PWM2（对应本套转接板 15 号针）。

## PWM 舵机规格与控制特性

云台选用 270° 旋转角度规格舵机，关键电气与机械参数如下：

| 参数项 | 技术指标 |
| --- | --- |
| 适配型号 | TB S-K15（15 kg·cm）/ TB S-K20（20 kg·cm） |
| 自重 | 58g（S-K15）/ 62g（S-K20） |
| 转动速度 | 0.16 s/60°（S-K15）/ 0.24 s/60°（S-K20）@ 7.4V |
| 额定转角 | 0～270° |
| 控制信号 | 50Hz PWM（周期 20ms），有效脉宽 500～2500μs |
| 供电规范 | 5.0～8.4V，瞬间峰值电流支持 3A |

舵机接线线序：棕/黑线为电源负极，红线为电源正极，白线为脉冲信号输入线。

### 供电方案说明

* **推荐独立供电（生产/展演）**：舵机满载瞬间电流较大，推荐使用 5V 3A（或 5.0～8.4V）独立稳压电源供电，并将电源地线与 K3 系统地（GND）相连共地，避免大动态负载拉低主控板级电压。
* **临时复用供电（现场调试）**：在现场缺乏独立电源的情况下，可临时接入转接板引出的 3.3V 引脚取电验证。因 3.3V 低于舵机标称工作电压（5V），舵机转速与峰值扭矩会有所衰减，正式部署时建议换回独立供电。

## 摄像头配置与物理边界

| 配置维度 | 参数指标 |
| --- | --- |
| 设备节点 | USB UVC 协议接口，通常枚举为 `/dev/video1` |
| 采集格式 | MJPG 1280×720 @ 30fps |
| 光学特性 | 定焦镜头，最佳识别人像距离为 0.5～2.0 米 |
| 曝光模式 | 开机默认手动低曝光，需在软件初始化时指定为自动曝光 |

摄像头固定于云台摆动端，随舵机动作旋转。设备控制参数在 [configs/hardware.json](../configs/hardware.json) 中配置，服务加载时自动调用 V4L2 接口下发设定：

```json
"controls": {
  "auto_exposure": 3,
  "white_balance_automatic": 1,
  "focus_automatic_continuous": 0
}
```

其中 `auto_exposure=3` 开启光圈优先自动曝光，避免室内场景下因默认曝光时间过短造成画面黑斑。

## Linux GPIO 与系统权限配置

舵机驱动依赖访问 `/dev/gpiochip*` 设备节点并启用实时调度优先级。通过初始化脚本完成系统授权：

```bash
sudo ./scripts/setup_k3_gpio.sh              # 写入 udev 与 limits 策略
./scripts/setup_k3_gpio.sh --check           # 仅检测权限配置状态
sudo ./scripts/setup_k3_gpio.sh --uninstall  # 移除配置
```

脚本配置项包括：
1. 建立系统级 `gpio` 用户组（GID < `SYS_GID_MAX`），并将当前用户加入该组。
2. 配置 `/etc/udev/rules.d/60-k3-gpio.rules`，授权 `d4019000.gpio` 芯片节点的属组访问权限。
3. 配置 `/etc/security/limits.d/60-gpio-rtprio.conf`，向 `gpio` 组成员开放 `rtprio 80` 权限，以支持 `SCHED_FIFO` 实时调度。

修改后需重新登录终端会话使系统权限生效。运行 `id` 命令确认当前凭据中已包含 `gpio` 组。

## 运行状态与生命周期

* **硬件初始化**：主服务启动时申请 GPIO29 线路，并在专属进程中以 `SCHED_FIFO 80` 优先级绑定 CPU7 执行脉冲生成。主进程推理任务自动限制在 CPU 0～6 核心，避免时序争用。若 GPIO 申请失败，系统自动回退至模拟舵机模式，保障基础业务运行。
* **停发消抖机制**：每次转动完成且画面停稳后，脉冲进程主动输出零脉宽（`servo.hold: "release"`），消除微小脉冲抖动引发的云台机械微颤，避免画面晃动干扰人体静止判定。
* **安全退出**：接收中断信号（Ctrl-C）时，舵机平滑复位至待机角度并释放摄像头。异常强制终止（`kill -9`）主进程可能导致脉冲子进程未回收而锁定引脚，如遇此情况执行 `pgrep -af spawn_main` 查明残留 PID 并予以终止。

## 故障排查

| 故障现象 | 排查方向 | 解决方案 |
| --- | --- | --- |
| 提示引脚已被占用 | 历史脉冲子进程残留 | 执行 `pgrep -af spawn_main` 查找并终止残留进程 |
| 无法打开 gpiochip 节点 | 用户权限未生效 | 运行 `id` 检查是否包含 `gpio` 组，配置脚本后需重新登录会话 |
| 脉冲时序抖动过大 | 实时调度未生效或 CPU 抢占 | 检查 limits.d 配置是否生效，核对服务核心绑定参数 |
| 舵机无响应 | 接线引脚不匹配或电平不符 | 确认信号线接入转接板 15 号脚，运行 `servo_gpio_test.py` 测量跳变 |
| 舵机颤动发烫 | 供电功率不足或机械堵转 | 检查供电电压是否达到 5V 以上并确认共地良好，排查机械干涉 |
| 画面全黑 | 曝光参数未正确初始化 | 检查 `camera.controls` 是否包含 `auto_exposure=3` |
* Linux GPIO 字符设备 uAPI：`Documentation/ABI/testing/gpio-cdev`，实现细节见 [docs/servo.md](servo.md)
